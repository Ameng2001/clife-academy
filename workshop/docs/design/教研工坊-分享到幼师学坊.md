# 教研工坊 → 幼师学坊：「分享到幼师学坊」

2026-10-22。对应幼师学坊仓库 `docs/WORKSHOP-SHARE-DESIGN.md` 的 A 路（工坊内置按钮）；接口契约在同仓库 `docs/WORKSHOP-SHARE.md`。

一门课在班里**用过**以后，教师把它作为「课程成果」分享到幼师学坊。工坊起草不算成果，用过并改过才算。学坊收到后走园长同意、审核人入库，入库记积分；别的教师能标「用过，有效」、能「改编这门课」。

## 工坊这边有两件实现

| 形态 | 在哪 | 做什么 |
|---|---|---|
| 插件 skill | `workshop-core/skills/share`，`/workshop-core:share {project}` | 在 Claude Code 里走完整流程：用过再分享的门槛、四栏表、两个开关、提交、署名一句。脚本 `workshop-core/scripts/share_academy.py` |
| 页面原型 | `apps/teaching-workshop-ui-v3/export-bundle.html` | 交付页右上角「分享到幼师学坊」按钮与四栏表弹层，给线上版（jiaoyan.clife.cn）照着做 |

线上版的真实实现不在这个仓库；这里的 skill 是可运行的参考实现，原型是界面规格。

## 按钮在哪、何时亮

课程工作台「交付」页，和「一键导出」并排。课程状态「未完成 / 待提交」时按钮灰，鼠标放上去说「用过再分享」；「审核通过」（`approved` / `shipped`）或教师自己标过「已在班里用过」（`status.json` 的 `used_in_class: true`）才亮。

## 四栏表

前三栏工坊预填、教师可改，第四栏必须教师手打：

1. **标题、管线、年龄班、周数、领域** —— 从信息采集带出来。管线对应：`pbl-huamei` → `pbl`，`thematic-curriculum` → `theme`，`five-step` → `activity`。
2. **简介**（≥ 50 字）—— 预填课程的「主题由来」或项目导览第一段。
3. **文件** —— 勾选要带的产物，每个勾选项要一个可长期访问的 https 下载地址；学坊不存文件，失效由工坊负责。默认只勾网络图和周计划，教案包太大默认不勾。
4. **在起草稿上改了什么**（至少一条，每条 ≤ 120 字）—— 空的提交按钮不亮。三个提示词「幼儿应答」「材料」「环节数」各起一行「把 ___ 改成 ___，因为 ___」。**工坊不替教师生成这一栏，也不从课程的修改记录、评审意见、活动反思里摘。**

两个开关（照懂了鸭）：允许改编（默认开）；文件对谁可见（默认全平台 / 本共同体 / 本园）。简介与「改了什么」始终全平台可见。

## 令牌

教师在幼师学坊「设置 → 接口令牌 → 新建一枚投稿令牌」，标签写「教研工坊」，粘到工坊的个人设置（插件版是 `.workshop/config.yaml` 的 `academy.token`，已加进 `.gitignore`）。没粘过的教师点按钮，弹一步说明，附学坊地址。工坊不替教师建学坊账号。

## 提交与回写

`POST /api/works`，带 `source: { courseId, url }` 与两个开关。成功后工坊在课程上记学坊给的 `work.id`（插件版写在 `status.json` 的 `academy` 段：`work_id / status / url / shared_at`），按钮变成「已分享 · 在幼师学坊里看」。学坊退回后再改再交带同一个 `id`。

教师只想先落草稿、回学坊再补「改了什么」：`POST /api/works/draft`（不带 changes）。

## 署名仪式（可跳过）

提交成功那一屏问一句「给同行留一句话？」，≤ 80 字，存进 `message`，显示在学坊卡片上。不是评价、不是总结。

## 改编回跳（待做）

学坊里「改编这门课」目前在学坊开一张预填表。工坊支持 `?from=<courseId>` 复制课程后，学坊那边把按钮改成跳到工坊开新课，交回来时带 `adaptedFrom: <work.id>`。

## 不做的

- 不替教师写「改了什么」。
- 不带工坊的课程评分、送审次数、评审意见。
- 不带幼儿姓名与正脸；教案里预设的幼儿应答是剧本。
- 不自动把每门课都推到学坊。
