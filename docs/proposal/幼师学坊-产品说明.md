第二节是它与教研工坊的关系，第三节是它和一般教师培训平台不一样的地方。只想了解产品的人读完前三节即可，后面是逐页截图。

## 一、一句话

教师按岗位走关，在平台上真做一次就算一关；做过的事、做过的课分享回来，成为别人的素材。学是 PGC，由运营方与专家编好 16 条路径 105 关；分享是 UGC，来自教研工坊和园里真实做过的事。两边都记积分，积分是平台唯一的资产。

三端一个账号：网页端（教师的主要工作面，也是园长、区县、运营的看板）、微信小程序（教师随手学、随手查）、教研工坊（做课的工具，钱包页在那边）。统一登录后三端同一个 uid。

## 二、与教研工坊的关系

两件产品，一个闭环。教研工坊是专业的课程研究工具：教师输入一句话，管线起草主题网络图、周计划、逐节教案、量表，教师逐步确认。幼师学坊是教师发展平台：学该学的，分享做过的。

| | 教研工坊 | 幼师学坊 |
|---|---|---|
| 教师来做什么 | 研究一门课，把它做出来 | 学该学的，分享做过的 |
| 内容从哪来 | 教师输入，管线起草，教师确认 | PGC 路径与关卡；UGC 专家案例与课程成果 |
| 产出 | 教案、周计划、量表等文件 | 积分、学时证明、证书；入库的案例与成果 |
| 判断权 | 教研主任 | 园长同意、审核人入库 |
| 钱包页 | **在这里**，只渲染不算账 | 不做钱包界面，只提供接口 |

闭环是这样转的：

1. 教师在幼师学坊按岗位走关、分享成果，自动记积分。
2. 积分是教研工坊的工具额度。起草一门主题式课程按周扣 30 积分，项目式 40，单节活动 10；改编学坊里已入库的成果打五折。
3. 教师在工坊做出来、班里用过的课，点「分享到幼师学坊」回流，成为课程成果。必须写「在起草稿上改了什么」，工坊起草不算成果，用过并改过才算。入库记积分，别的教师可以标「用过，有效」，也可以改编，改编带来源链。
4. 课程成果和专家案例一起，是下一轮 PGC 的素材：名师讲堂讲它、合集收它、研讨关拿它出题。

**积分与钱包的口径，一共六条：**

- **只有积分一种资产。** 没有学分、没有下载次数、没有可赠送的东西。继续教育学时是时长记录，证书、勋章、称号是记录，都不是资产。
- **自动到账，不奖刷量。** 学（过关 10、走完路径 50、取得证书 100）、贡献（案例入库 20、课程成果入库 30、讲堂上台 50）、互动（被标「用过，有效」5、点评别人 3，每项有日限月限）三类事件自动记，规则表运营后台可改。签到、在线时长、浏览、点赞、邀请一律不给。
- **不是货币。** 不可转赠、不排行、不公开余额、不与考核挂钩、不充值不提现。
- **两个去处。** 教研工坊与接入工具的额度；教学物料商城（教具、绘本、耗材、讲堂名额，本地运营方上架、寄到园，不上购物卡）。
- **两本账：积分与园所额度。** 园所额度是园长从园所额度池分给教师的，只能用在工具上，商城不能用；工具扣减先扣额度再扣积分。没学过的教师也能用工坊做课，由园所给额度。
- **钱包页只在工坊。** 余额、四栏小计（学与贡献、互动、工具扣减、商城）、流水、园所额度来龙去脉全部由学坊算好给工坊，工坊只渲染。学坊的「我的」页只显示积分、园所额度和最近几笔，完整明细指向工坊钱包页。

工坊服务端接六条接口（握手、余额、报价、扣减、钱包整包、来源核对），用 `TOOLS_API_KEY` 调，幂等扣减。学坊侧已全部就绪，附联调脚本；工坊线上版的钱包页与分享按钮待做，整理版见仓库 `workshop-share/`。

## 三、和别的教师培训平台不一样的地方

1. **「做」是在平台上真做一次。** 每关讲、看、做、测。工具关靠柳州平台回传的实操事件判通，不是看完视频点确认；实践关交证据加点评；研讨关作答加点评。精品微课是关卡的讲段，遇到事可以直接查，不受解锁限制，但看完不单独给积分。
2. **按岗位编，不按课程编。** 保健医、班级教师、保育员、信息接口人、园长五个岗位各一条路径，再加六个领域、三个阶段（入职、骨干、管理）、区县管理员，以及一条「用教研工坊做课」。
3. **不打分、不排名、不比人。** 能力地图七领域只给本人看，不作考核依据；共同体不显示浏览与点赞数，没有关注；斗课、共同体赛、市级展示评作品不评人，没有分数与名次；园长与区县看板只看应用情况与中位数，不列哪园哪人。
4. **UGC 有门槛。** 专家案例实名投、园长同意、审核人入库，标「可直接用 / 需改编 / 只看思路」；课程成果必须写「改了什么」；改编带来源链；由案例生成轻形态（家长会课件、改前改后卡、记忆卡）。
5. **AI 只起草，人确认。** Coach 按学习记录排一学期，教师采不采用自己定；Agent 可以替教师整理成果投稿，但不替教师写「改了什么」、不替教师点提交、不替教师注册账号。
6. **红线写进代码。** 十条平台口径进所有提示词、有专门页面：不用数字产品生成观察记录或评价幼儿，幼儿不对屏，不做陪伴聊天类，不讲留痕迎检，素材里不出现真实幼儿姓名与正脸。
7. **园所应用体检只看平台使用数据。** 十二项探针每周自动生成，不含幼儿个人数据，不作为教师考核依据，区县只看汇总。
8. **继续教育学时可回填。** 发展档案按时段汇总实践关时长，出具学时证明，格式按市教育局认定要求；档案随人迁移，教师换园带着走。
9. **开放给 Agent。** 公开一份 Skill 文档和投稿令牌，教师可以在自己的 Claude、Cursor 等客户端里让 Agent 替自己整理成果，令牌只读与投稿分开，可随时作废。

## 四、角色与登录

| 角色 | 网页端 | 小程序 | 备注 |
|---|---|---|---|
| 教师（五个岗位） | 学、分享、档案、Coach、设置令牌 | 五个 tab 与二级页 | 王老师 |
| 园长 | 另有园长看板、点评、园所额度分配、带教配对、本园体检 | 首页多园所面板、额度分与收 | 赵园长 |
| 区县管理员 | 区县看板：覆盖率与中位数、共同体、体检汇总 | 区县看板页 | 无园所 |
| 运营管理员 | 运营后台：六组事、公告、积分规则、园所额度充值、审计 | 不做 | 本地运营方 |
| 审核人、策展人 | 案例与成果审核、合集 | 不做 | 教师加标记 |

登录三条路：柳州平台统一登录（ticket 或 oauth2）、微信登录（小程序）、本地开发桩。三端一个 uid，进度随账号同步。
