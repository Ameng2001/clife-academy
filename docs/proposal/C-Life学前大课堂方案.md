> 内部方案。依据：三篇工具文章（白板动画 Skill、悠衔游戏化学习引擎、Web-Check），神策学堂（school.sensorsdata.cn）栏目与课程页，柳州《数智幼教培训-园医模块》《数智幼教培训模块（教学）》两份课件，以及柳州 90 所园交付实施方案。

## 一、结论

**大课堂的定位是「交付之后的持续培训载体」，不是另做一个内容站点。** 柳州交付方案里的园内培训由 4 名讲师在 11 月底前做完，之后新入职教师的带教、试运行期的补训、终验后三年的能力维持都缺一个固定载体。大课堂接住这三件事：按岗位分路径闯关，每关「看一段微课、在平台上做一遍、答三道题」，平台记录实操是否真的完成。

**三个工具各补一块。**

| 工具 | 补的环节 | 怎么用 |
|---|---|---|
| 白板动画 Skill（srt-whiteboard-animation） | 内容生产 | 把课件逐字稿转成 25—35 秒一幕的白板手绘微课，讲清「为什么做、流程是什么」；操作步骤仍用录屏 |
| 悠衔（Dabble） | 学习形态 | 借用「蒸馏图文＋即时测验＋答错即解释」的闯关结构和「教材 JSON 导入」的内容格式；不借用宠物、开宝箱类激励 |
| Web-Check | 学情诊断 | 借用「输入一个对象、并行跑几十项检查、聚合成一张看板＋JSON」的模式，做「园所应用体检」，按体检结果给园所推课 |

**神策学堂提供的是栏目骨架和收费结构。** 它的六个栏目（大咖分享、系列课程、单节精品、干货文章、精品话题、资料库）加上 SA 分析师认证和客户专区，可以一一对应到学前场景。最值得借的是两点：一是认证课分期开班、按期收费（2026 年第一期 25 节课、¥2,999、8,029 人已购）；二是资料库按「职业方向 × 行业方向」两维筛选，对应到我们是「岗位 × 场景」。

**上线节奏跟交付走。** 11 月 20 日前上线第一版（园长、保健医、教师、保育员、信息接口人五条路径共 34 关），赶在 12 月 1 日试运行开始前可用。园长路径首期上线，园长在试运行期就能用体检卡安排补训；寒假（2027 年 1 月 23 日起）开放区县管理员路径与「寒假研修」；春季学期开第一期岗位认证。

## 二、三个工具拆解

### （一）白板动画 Skill：字幕进、手绘视频出

**是什么。** GitHub 开源项目 srt-whiteboard-animation（MIT 协议，文章发布时 3.8k Star），以 Skill 形式装给 Claude Code、Codex 等助手使用。输入字幕文件，按 25—35 秒一幕拆分镜，AI 按统一风格生成线稿，再按字幕顺序逐块勾线、上色，渲染成 MP4，多幕合并成片。风格固定为暖米黄纸底、深灰素描线、少量红橙蓝点缀，画面不放文字。

**机制上值得借的。** 每一步都要人确认后才往下走：分镜、线稿、像素级标注、分区检查、预览台调整、逐幕渲染、成片。画面元素的出场顺序由字幕决定，音画天然对齐，不用事后对时间轴。自带 preview.html，可在浏览器里调整区域、顺序和时序，不碰代码。

**用在大课堂。**

1. 每个场景的「为什么做、整体流程」用白板微课。例如园医路径的「因病缺勤 → 聚集预警 → 园医排查 → 智能体给出处置方案」，一幕讲一个环节，四幕约两分钟。
2. 素材来源是现有课件。两份课件已按场景组织，逐字稿可直接改写成字幕；按本仓库口径，逐字稿先过一遍去 AI 腔再进流水线。
3. 旁白用统一的合成语音生成音频，字幕时间轴由语音合成结果导出，再交给 Skill。

**边界。** 白板画不出平台界面，「点哪个按钮」必须用录屏。文章也提到它更适合几十秒一幕的短内容，长视频要多幕拼接、工作量线性上升，所以单个微课控制在 3 分钟以内。画面里不画幼儿面部特写，不出现真实园所、真实幼儿。

### （二）悠衔（Dabble）：把专业知识拆成闯关

**是什么。** 一套通用的游戏化学习引擎，把任意领域知识拆成「闯关＋即时测验」。每关先读一段蒸馏过的图文，再做理解型测验，答错立即解释；用金币、开宝箱、宠物养成做激励。支持导入 JSON 格式教材，也能用 AI 从开源 Skill 生成教材，内置 11 本教材（如「AI Agent 入门」126 关）。形态为移动端 H5，目标用户是利用碎片时间自学的成年人。文章未给出开源地址，只作产品形态参考。

**值得借的。**

1. **关卡粒度。** 一关只讲一件事，读完立即测，答错立即解释。对应到我们，一关对应课件里的一个「实操任务」。
2. **教材即数据。** 课程以 JSON 描述，可导入、可由 AI 生成。我们把课程包定义成 JSON（关卡、图文、视频、测验、实操校验事件），课件改版后重新生成，不用手工搬运。
3. **碎片时间、手机端。** 教师的空档在午睡和离园后，课程必须能在小程序里 5 分钟学完一关。

**不借的。** 宠物养成、开宝箱、抽奖与教师的专业身份不符，也容易被理解为「刷时长」。激励改用学分、岗位徽章与认证（见第八节）。

### （三）Web-Check：一个入口，看清全部底牌

**是什么。** 开源网站情报工具（MIT 协议，34k+ Star）。输入一个网址，后台并行调用 38 项以上检查（IP、DNS、SSL、端口、安全头、技术栈等），结果聚合成卡片式看板，同时每项检查有独立 API、另有一个聚合 API 返回统一 JSON。支持 Docker 自托管，可关闭敏感检查、限流、屏蔽内网地址。

**值得借的不是功能，是模式。**

1. 一个对象（园所）进去，一组相互独立的检查（探针）并行跑，结果统一成看板加 JSON。
2. 每个探针可单独开关；缺数据的探针自动跳过，不影响整体报告。
3. 报告既给人看，也给程序用：JSON 结果直接驱动推课。

**用在大课堂：园所应用体检。** 见第六节。它是大课堂和平台之间的接口：体检发现哪个场景用得少，就给对应岗位推哪几关。

**边界。** Web-Check 本身是安全侦察工具，代码不复用，只借架构思路。体检对象是园所的平台使用情况，不评价幼儿，也不作为考核教师的依据。

## 五、栏目与课程设计

### （一）栏目

1. **首页**：本人岗位路径进度、本周待学关卡、下一场园长大讲堂、本园体检结果对应的推荐关卡。
2. **学习路径**：六条岗位路径，地图式展示，关卡依次解锁。
3. **场景微课**：全部关卡按场景浏览，不受解锁限制，供查找操作方法。
4. **园长大讲堂**：直播预约、回放、讲义下载。
5. **情景练兵**：每周一道情景题，教师作答，讲师点评，优秀作答在本地专区展示。
6. **资料库**：模板、手册、课案，按岗位和场景两维筛选。
7. **本地专区**：登录后可见，显示本地讲师、本园工单、交付与运维通知。
8. **我的**：学分、徽章、认证证书、学习记录导出。

| 8 | 数智体能：国体测评流程 | 查看本班测评结果 |

**信息接口人路径（2 关）**：设备在线检查与离线判断、报修流程与日常巡检记录。

**园长路径（6 关）**，取自园长工作台功能与本方案的体检、合规口径：

| 关 | 主题 | 实操校验 |
|---|---|---|
| 1 | 工作台总览：先看风险与待办，再看全园概况 | 打开工作台一次 |
| 2 | 风险与待办处置：查看告警依据，指派岗位并设定回执时间 | 指派一条待办 |

| 4 | 回执与复盘：为已完成事项写复盘结论，收入本园做法库 | 完成一条复盘 |
| 5 | 读体检卡：为需关注项安排补训 | 生成一次补训通知 |
| 6 | 数据与家长沟通：监护人告知同意、岗位最小权限、回应家长关于数据用途的询问 | 核对一次岗位权限 |

园长路径首期上线，原因是体检卡和补训安排从 12 月 1 日试运行起就要用，园长要先会读、会派。指标与体检只用于本园改进，课程中明确不排名、不作为教师考核依据。园长工作台中「分析幼儿发展」类功能不进课程。

首期共 34 关。区县管理员路径放在寒假上线。

### （三）单关标准

每关由四段组成，总时长 8 分钟以内：

| 段落 | 形态 | 时长 | 要求 |
|---|---|---|---|
| 讲 | 白板微课 | 1—2 分钟 | 讲为什么做、流程是什么，一幕一意 |
| 看 | 录屏 | 1—2 分钟 | 真实界面，逐步标注点击位置 |
| 做 | 平台实操 | 3 分钟左右 | 在本园账号或演示园完成任务 |
| 测 | 即时测验 | 1 分钟 | 3 道情景题，答错立即给出解释并链接到对应录屏片段 |

实操校验以平台事件为准：学员完成规定操作后，平台回传事件，该关才算通过。没有本园数据的学员（如新入职尚未分班）在演示园完成。

## 六、园所应用体检

### （一）体检维度

体检以园所为单位，每周自动生成一次，不需要人工填报。

| 探针 | 检查内容 | 数据来源 |
|---|---|---|
| 账号覆盖 | 各岗位账号开通数与教职工数之比 | 平台账号 |
| 基础数据 | 班级、幼儿、健康档案字段完整度 | 平台基础数据 |
| 设备在线 | 各类设备在线数量、连续离线设备 | 设备管理 |
| 晨午检 | 晨检记录覆盖的在园日数 | 晨检模块 |
| 出勤与请假 | 出勤确认及时率、家长端请假使用 | 出勤、请假模块 |
| 疾病管理 | 疾病记录有追踪、有康复结论的比例 | 疾病管理模块 |
| 膳食 | 当周是否发布食谱 | 膳食模块 |
| 睡眠 | 睡眠垫在线与数据回传天数 | 睡眠模块 |
| 体能 | 本学期是否完成一次测评 | 体能模块 |
| 教研 | 本月课案数 | 教研工坊 |
| 学习 | 各岗位路径完成率 | 大课堂 |
| 工单 | 操作咨询类工单数量与重复问题 | 问题台账 |

探针可单独开关。新上线园所前两周只开账号、基础数据、设备在线三项。

### （二）输出与推课

1. **园所体检卡**：园长端可见，每个探针显示正常或需关注，附对应的关卡或手册链接。
2. **推课规则**：某探针连续两周需关注，向对应岗位推送相应关卡。例如「疾病记录无康复结论比例偏高」推保健医第 8 关；「操作咨询工单集中在批量出勤」推教师第 2 关和保健医第 3 关。
3. **补训名单**：体检结果汇总给本地运营方，作为补训和巡园的排期依据，与交付方案中「使用情况偏低的园所安排补训与跟岗指导」对接。

### （三）边界

体检只看园所对平台的使用情况，不出现单个幼儿的数据，不对幼儿做任何评价。体检结果用于园所自我改进和安排补训，不对外公布园所排名，不作为对教师的考核依据。面向区县教育局只提供汇总口径。

## 七、内容生产流水线

### （一）流程

1. **拆题**：以课件为底稿，每个实操任务定为一关，写出学习目标与校验事件。
2. **逐字稿**：每关写 300—500 字逐字稿，去 AI 腔后由产品讲师审定。
3. **白板微课**：逐字稿合成语音、导出字幕，交给白板动画 Skill。分镜、线稿、标注、成片四个确认点由内容编辑把关。
4. **录屏**：在演示园录制操作，演示园数据全部虚构，不出现真实幼儿信息。
5. **测验**：每关 3 道情景题，由 AI 依据逐字稿起草，讲师审定，每题附答错解释。
6. **打包**：按课程包 JSON 格式组装关卡，上架到大课堂。
7. **复审**：平台版本更新后，按功能清单找出受影响的关卡，只重录录屏段。

### （二）课程包格式

课程包以 JSON 描述，字段包括：路径、关卡序号、岗位、场景、学习目标、白板微课地址、录屏地址、图文要点、测验题与解释、实操校验事件、适用平台版本。格式确定后，课件改版、新增场景、复制到其他地区，都只需重新生成课程包。

### （三）产能

| 环节 | 每关用时 | 首期 34 关合计 |
|---|---|---|
| 逐字稿与审定 | 0.5 人日 | 17 人日 |
| 白板微课（含四个确认点） | 0.5 人日 | 17 人日 |
| 录屏与标注 | 0.3 人日 | 10.2 人日 |
| 测验与打包 | 0.2 人日 | 6.8 人日 |
| 合计 | 1.5 人日 | 51 人日 |

## 十一、合规边界

1. **幼儿不对屏。** 大课堂只面向成人。区角 AI 萌宠、机器人对话等面向幼儿的陪伴类功能，不进课程主线；悟空机器人只讲教师端的课中操控。
2. **观察记录。** 课程统一表述为「教师口述、AI 整理、教师审定」，不讲「AI 自动生成观察记录」「评价幼儿」。
3. **不讲留痕迎检。** 课程讲「一次采集、多方复用」和「减少重复录入」，不以「满足检查」作为学习理由。
4. **素材隐私。** 微课、录屏、案例中不出现真实幼儿的姓名、面部与健康信息；园所案例需园长书面同意。
5. **体检数据。** 只看使用情况，不出现单个幼儿数据，不排名，不作考核依据。
