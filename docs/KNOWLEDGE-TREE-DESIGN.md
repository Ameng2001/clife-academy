# 知识树：把学坊的内容挂到一棵标准树上（设计稿，2026-10-22）

## 一、先说能借到什么

公开报道里，懂了鸭的「知识树」只有一句：平台「提供丰富的知识树和国家课程标准来保证内容的准确性和可靠性」。没有结构说明，没有截图。能确定的只有三点：树以国家课程标准为骨架；作品按学段、学科两个标签挂上去；社区里的作品可以改编，改动留「创作脉络」。

所以这里借的是**做法**，不是它的树。它的树是 K12 学科知识点，给孩子用；学坊的树要给教师用，骨架只能是教师专业标准，不是幼儿学什么。

## 二、学坊现在已经有一棵树，但只有一层

| 现有 | 是什么 | 缺什么 |
|---|---|---|
| 七个领域（`capability.js` `DOMAINS`） | 《幼儿园教师专业标准》专业能力维度的七个领域，案例、斗课、练兵、成果、合集都按它打标签 | 只有一层，一个领域下面几十关、几十条案例混在一起，找不到「家长在群里质疑午睡」这种具体的事 |
| 能力地图（`/map`） | 七个领域各一个状态：有证据 / 在做 / 还空着 | 粗到只能告诉教师「沟通与合作还空着」，不能告诉她空在哪一条 |
| 16 条路径 105 关 | 按岗位、领域、阶段编的学习顺序 | 路径是「走」的顺序，不是「查」的结构；一关只属于一条路径，别的路径里相关的关互不知道 |
| 案例、成果、讲堂切片、合集、练兵题、轻形态 | 内容本身 | 各自一张表，各自一套标签，没有共同的挂点；工坊投来的课也只有五领域标签 |

换句话说：内容够，树不够。补的是中间两层。

## 三、树长什么样

三层，全部来自教育部文件，不自造名词。

```
领域（7）            ← 《幼儿园教师专业标准（试行）》专业能力维度，已有
 └ 条目（约 30）      ← 同一文件该维度下的「基本要求」，每条一句话
    └ 知识点（约 150） ← 条目下教师要会的一件具体的事，对应《3–6 岁儿童学习与发展指南》
                         《幼儿园保育教育质量评估指南》的具体目标或考查要点，以及本平台关卡的 scene
```

举一条：

```
沟通与合作
 └ 「与家长建立良好关系，主动沟通，形成教育合力」
    ├ 家长会的组织与发言           ← 评估指南「家园共育」考查要点；关 comm-3
    ├ 家长在群里公开质疑时的第一条回复 ← 关 comm-5（研讨关）；练兵题；案例 ×4
    ├ 特殊需要幼儿家长的沟通       ← 评估指南「关注有特殊需要的幼儿」
    └ 日常接送时的两句话           ← 关 comm-1
```

规则：

- **节点是教师的事，不是幼儿的事。** 「幼儿能数到 10」不是节点，「怎么在生活里支持幼儿数数」才是。《指南》的目标只做节点的依据，不做节点本身，否则树就变成评幼儿的量表（docs/ROADMAP.md 十二节、`policy.js` 第二条红线）。
- **节点要能挂东西。** 一个知识点至少挂得上一关、一条案例或一道练兵题，挂不上的不建。先建有内容的，空节点以后再补，树不求全。
- **三层封顶。** 再往下是内容本身。
- **每个节点带出处。** 写明来自哪份文件哪一条，树页能点开看原文（资源库已内置教育部文件原文，`resources-seed.js`）。

数据：`api/academy/tree-data.js` 一份只读表，`{ key, parent, name, source:{doc, clause}, scenes:[], levelIds:[] }`。领域层沿用 `DOMAINS` 的七个 key，条目与知识点的 key 用 `comm.parent.meeting` 这种点分法，稳定、可读、能当标签。

## 四、功能点

按价值排序，前四条是树的本体，后四条是树带来的新能力。每条写清学坊侧、小程序侧、工坊侧分别做什么。

### T1 树页：按树找内容

- **学坊**：`/tree`，左栏七个领域，中间条目，点一个知识点进节点页。节点页把挂在它上面的东西按类分组：关卡、专家案例、课程成果、讲堂切片、练兵题、轻形态、合集，各给数量与前三条，点开去各自的页。筛选只保留阶段（入职 / 成长 / 骨干 / 管理）和年龄班，不做排序选项，默认按入库时间。
- **接口**：`GET /api/tree` 整棵树带每节点的内容计数；`GET /api/tree/:key` 节点详情与挂件分组。计数按当前用户可见范围算（成果的 filesScope、合集的范围）。
- **小程序**：「路径」tab 顶上加一个入口「按知识点找」，节点页只列关卡、案例、成果三类。
- **工坊**：不做界面，用 T4 的标签。

### T2 内容挂树：给每样东西打节点标签

- 关卡：由 `tree-data.js` 的 `levelIds` 定，不改关卡数据。
- 案例、课程成果、练兵题、讲堂切片、合集、轻形态：各加 `nodes: [key]`，一到三个。
- 谁打：提交人自己选（表单里一个树形选择器，默认按领域展开）；审核人入库时可改；已入库的存量由管理员在后台批量补，补之前节点页按领域标签兜底显示。
- 校验：key 必须在树里；不在的 400 `node`。
- **工坊**：投稿接口 `POST /api/works/draft` 接 `nodes`，Agent 分享 Skill 里加一段「从树里挑一到三个知识点」，树通过 `GET /api/tree` 公开给 Agent 读（不要登录，和 Skill 一样）。

### T3 能力地图下钻到节点

- 现在的 `/map` 是七行，每行一个状态。改成每行可展开，展开后按条目列知识点，每个知识点三种状态同现在：有证据 / 在做 / 还空着。证据算法不变（`capability.js`），只是把关卡归到节点而不是归到领域。
- 「还空着」的节点直接给「去学」：挂了关卡的指到关卡，只挂了案例的指到案例。这是树对教师最直接的用处：**知道自己空在哪一条，而不是空在哪一片。**
- 仍然只给本人看、不打分、不排行、不作考核依据（现有口径一字不改）。园长看板不加节点级汇总，只保留现在的领域级中位数。
- **小程序**：「我的」页能力地图同步，展开到条目，知识点不展（屏幕小）。

### T4 工坊与学坊的共同词表

- 树的 key 是两边共用的标签。工坊起草一门课时可以带 `nodes`，分享到学坊时原样带回；学坊的改编链（`adaptedFrom`）加上节点，节点页能看到「这个知识点下有哪些课被改编过几次」。
- 工坊侧只需要在导出的信息采集表里多一行「对应知识点」，不改引擎。线上版实现时记进 docs/WORKSHOP-TODO.md。

### T5 Coach 按树排学期

- Coach（`coach.js`）现在按领域和阶段排一学期 16 周。改成按节点：先列本人「还空着」的节点，按阶段过滤，再按节点挂的关卡排周。排出来的每周多一行「这周补的是哪一条」。
- 不新增模型调用，排序是规则。

### T6 讲堂与合集按节点收

- 讲堂包切片（`lectures.js`）切出来后由讲者或管理员挂节点，节点页就有了「名师怎么讲这一条」。
- 合集（`collections.js`）加一种自动合集：「某节点下全部入库内容」，不用人工攒，节点页的「收为合集」一键生成，范围沿用合集现有的四档。

### T7 练兵题与研讨关按节点出题

- 练兵题（`drills.js`）加 `nodes`，出题人从树里选节点出题，答完的优秀作答进案例库时自动带同一个节点。
- 研讨关的题也标节点，答案进案例库同理。这样一个知识点下面会自然长出「题、答、案例」三样，树越用越厚。

### T8 空节点清单：给内容团队的待办

- 后台 `/admin` 加一块「树上还空着的节点」：没挂任何内容的、只有案例没有关卡的、一个月没新增的。这是内容团队的选题单，也是名师讲堂的选题来源。
- 只给管理员看，不对教师显示「这个知识点还没内容」。

## 五、不借的

- **不做知识点刷题。** 树是找内容和看自己空在哪的，不是题库。测验仍然每关三题以内。
- **不做幼儿的知识树。** 树上没有「幼儿应达到」的节点，《指南》只做依据。
- **不做热度。** 节点不显示浏览量、投蛋、下载数，按时间排。
- **不做 AI 自动打标签。** 节点由人选，模型最多在表单里给三个建议并标明「建议」，和现在的草稿规则一致。
- **不做 K12 的学段学科两维。** 学坊的两维是阶段和年龄班，已经有了。

## 六、顺序与体量

| 步 | 做什么 | 体量 |
|---|---|---|
| 1 | `tree-data.js` 建树：七领域下的条目照《专业标准》抄，知识点先建现有 105 关能挂上的，加案例库已有案例能挂上的，预计 80 到 120 个 | 内容工作为主，一两个晚上 |
| 2 | T1 树页与两个接口、T2 的字段与校验、存量按领域兜底 | 一个晚上 |
| 3 | T3 能力地图下钻，小程序同步 | 一个晚上 |
| 4 | T4 工坊词表（学坊侧接 `nodes`、Skill 加一段、`GET /api/tree` 公开）、T8 空节点清单 | 半个晚上 |
| 5 | T5、T6、T7 | 各半个晚上，按内容团队需要再排 |

第 1 步做完就能看出树好不好用：如果 105 关里有一半挂不到具体知识点，说明条目拆得不对，回头改树，不要往下做。

## 七、要你定的

1. 条目层照《专业标准》原文抄，还是允许合并改写？建议照抄，出处清楚。
2. 知识点层由谁定稿：本地运营方自己，还是请市教研员看一遍？这一项与 ROADMAP 十二节第 1 条是同一件事。
3. 先做哪个领域：建议「观察、记录与评价」和「沟通与合作」，这两条领域路径已经做完，案例也最多。
