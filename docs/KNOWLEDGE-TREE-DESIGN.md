# 教师发展树：知识与能力两根主干，阶段做纵轴（设计稿，2026-10-22）

## 一、先说能借到什么

公开报道里，懂了鸭的「知识树」只有一句：平台「提供丰富的知识树和国家课程标准来保证内容的准确性和可靠性」。没有结构说明，没有截图。能确定的只有三点：树以国家课程标准为骨架；作品按学段、学科两个标签挂上去；社区里的作品可以改编，改动留「创作脉络」。

借的是**做法**：一棵标准树做骨架，所有内容挂上去，学习者的进度落在节点上。它的树是 K12 学科知识点，给孩子用。学坊的树给教师用，骨架是教师专业发展本身：**教师要懂什么，要会做什么，在哪个阶段该到哪一步。**

## 二、骨架：《幼儿园教师专业标准》的两根主干

《幼儿园教师专业标准（试行）》分三个维度十四个领域六十二条基本要求。树取其中两个维度做主干，第三个维度不进树：

| 维度 | 进不进树 | 为什么 |
|---|---|---|
| 专业知识（3 领域） | **知识主干** | 幼儿发展知识、幼儿保育和教育知识、通识性知识。教师要「懂」的。 |
| 专业能力（7 领域） | **能力主干** | 环境创设与利用、一日生活组织与保育、游戏活动支持与引导、教育活动计划与实施、观察记录与评价、沟通与合作、反思与发展。教师要「会做」的。现有七领域就是它。 |
| 专业理念与师德（4 领域） | 不进树 | 理念与师德不是关卡能教会、证据能证明的。它已经落在口径库（`policy.js` 十条红线）和每关的素材规则里，是树的边界，不是树的节点。 |

纵轴沿用 ROADMAP 第一节的四个阶段：入职、成长、骨干、管理。每个节点标它应该在哪个阶段到位，树 × 阶段就是教师发展地图。

学坊现在只有能力主干的第一层（七领域），知识主干完全没有，阶段只标在路径上没标在内容上。补的就是这三样。

## 三、树长什么样

两根主干各三层，全部来自教育部文件，不自造名词。

```
知识主干                                   能力主干
├ 幼儿发展知识                              ├ 环境创设与利用
│ ├ 条目：《专业标准》该领域的基本要求         │ ├ 条目：《专业标准》该领域的基本要求
│ │ ├ 知识点：3–4 岁幼儿的动作发展特点  [入职]  │ │ ├ 能力点：按主题更替一面墙的幼儿作品  [成长]
│ │ └ 知识点：个体差异与特殊需要的识别  [成长]  │ │ └ 能力点：调整一个区角的材料投放    [入职]
├ 幼儿保育和教育知识                        ├ 一日生活组织与保育
│ ├ 条目：掌握《指南》五领域的目标与建议       ├ 游戏活动支持与引导
│ │ └ 知识点：语言领域「倾听与表达」的目标     ├ 教育活动计划与实施
│ └ 条目：一日生活各环节的保育要求            ├ 观察、记录与评价
│   └ 知识点：午睡环节的安全与常规  [入职]     ├ 沟通与合作
└ 通识性知识                                └ 反思与发展
  └ 条目：教育法律法规
    └ 知识点：《未成年人保护法》里与幼儿园有关的条款  [入职]
```

- **领域层**：十个，照《专业标准》。
- **条目层**：两根主干共约四十条，照《专业标准》该领域下的「基本要求」原文抄，每条一句话，带条号。
- **叶子层**：知识点与能力点，预计各一百上下。知识点是一个教师应当懂的具体概念或规定，依据《3–6 岁儿童学习与发展指南》《幼儿园保育教育质量评估指南》《幼儿园工作规程》与法律法规的具体条文；能力点是教师要会做的一件具体的事，依据《评估指南》的考查要点与本平台关卡的 scene。

**两根主干之间有横向连线：每个能力点写明「做这件事要懂哪几个知识点」。** 这是树的核心，不是装饰：教师在能力地图上看到「调整区角材料投放」还空着，点开就知道先去懂「3–4 岁动作发展特点」和「区角材料的层次性」。工坊起草一门课也顺着这条线把依据带进教案。

规则：

- **节点是教师的，不是幼儿的。** 知识点可以是「《指南》语言领域的目标」，因为那是教师要懂的文件；但不能是「幼儿能复述故事」，那是评幼儿。《指南》《评估指南》只做依据，不做节点（`policy.js` 第二条红线）。
- **每个节点带出处**：哪份文件哪一条，树页能点开原文（资源库已内置教育部文件原文，`resources-seed.js`）。
- **每个节点标阶段**：入职 / 成长 / 骨干 / 管理，一个节点可以跨两个阶段。
- **叶子要能挂东西。** 知识点至少挂得上一段条文解读、一张记忆卡或一道测验题；能力点至少挂得上一关、一条案例或一道练兵题。挂不上的不建，树不求全。
- **三层封顶。** 再往下是内容本身。

数据：`api/academy/tree-data.js` 一份只读表。

```js
{ key: 'k.dev.motor34', trunk: 'knowledge' | 'ability', parent: 'k.dev.1',
  name: '3–4 岁幼儿的动作发展特点', stages: ['onboard'],
  source: { doc: '指南', clause: '健康·动作发展·目标 1' },
  needs: [] /* 能力点专用：要懂的知识点 key */, levelIds: [], scenes: [] }
```

key 用点分法，`k.` 知识主干、`a.` 能力主干，稳定、可读、能当标签。

## 四、两根主干的证据不一样

能力地图现在的口径是「证据不是分数，不和别人比，不作考核依据」，两根主干都沿用，但证据的来源分开：

| | 知识主干：懂了没有 | 能力主干：会不会做 |
|---|---|---|
| 证据 | 关卡测验里标了该知识点的题答对；记忆卡过了一遍；条文解读页读完并答了一题 | 工具关通过；实践关作品被点评通过；研讨关作答 |
| 状态 | 没碰过 / 看过 / 答对过 | 还空着 / 在做 / 有证据 |
| 不做 | 不做知识点刷题，不做正确率，不做遗忘曲线复习提醒 | 不打分、不排行、不作考核依据 |

知识的证据故意定得轻：读过、答对过一次就算。学坊不是题库，知识主干的作用是让教师知道「做这件事的依据在哪」，不是考她记没记住。

## 五、功能点

前四条是树的本体，后五条是树带来的新能力。每条写清学坊、小程序、工坊各做什么。

### T1 树页与节点页：按树找内容

- **学坊** `/tree`：顶上两个 tab「要懂的」「要会的」，左栏领域，中间条目，点叶子进节点页。可按阶段筛。
- 知识点页：条文原文与解读、记忆卡、挂了它的测验题、讲堂里讲到它的切片、「哪些能力点需要它」。
- 能力点页：「做这件事要懂什么」（横向连线，放最上面）、关卡、专家案例、课程成果、练兵题、轻形态、合集，各给数量与前三条。
- **接口** `GET /api/tree`（整棵树带计数，不要登录，给 Agent 和工坊读）、`GET /api/tree/:key`（节点详情与挂件，计数按当前用户可见范围算）。
- **小程序**：「路径」tab 顶上加「按知识点找」，节点页只列关卡、案例、成果、条文四类。

### T2 内容挂树

- 关卡：由 `tree-data.js` 的 `levelIds` 定，关卡数据不改；每关的测验题各标一个知识点（`qs[i].node`），这是知识证据的主要来源。
- 条文解读页（ROADMAP 第二节「讲」的来源里已列，还没做）：一页一条，挂一个知识点，页尾一道题。
- 记忆卡（`forms.js` 已有，按领域配《评估指南》关键指标）：改成按知识点配，一张卡一个知识点。
- 案例、课程成果、练兵题、讲堂切片、合集：各加 `nodes: [key]`，一到三个，可以同时挂知识点和能力点。
- 谁打：提交人自己选（树形选择器，两根主干都能选），审核人入库时可改，存量由管理员后台批量补，补之前按领域兜底。校验 key 在树里，否则 400 `node`。
- **工坊**：`POST /api/works/draft` 接 `nodes`；分享 Skill 加一段「从树里挑一到三个节点，能力点为主，顺手挂上它依据的知识点」。

### T3 能力地图改成发展地图

- `/map` 从七行变两块：「会做什么」七领域可展开到条目与能力点，「懂什么」三领域可展开到条目与知识点。状态口径见第四节。
- 每个「还空着」的能力点给「去学」，指到挂的关或案例；每个「没碰过」的知识点给「去看」，指到条文解读页或记忆卡。
- 顶上按阶段筛：选「成长」只看该阶段应到位的节点，教师一眼看到本阶段还差几条。这是阶段轴的用处。
- 仍然只给本人看。园长看板不加节点级汇总，只保留领域级匿名中位数。
- **小程序**：「我的」页同步，展开到条目，叶子不展。

### T4 工坊与学坊的共同词表

- 节点 key 两边共用。工坊起草一门课时带能力点，教案的「理论适配说明」段按 `needs` 把依据的知识点原文带进去；分享回学坊原样带回，改编链加节点，节点页能看到「这件事下有哪些课被改编过」。
- 工坊侧导出的信息采集表多一行「对应节点」，不改引擎。线上版实现时记进 docs/WORKSHOP-TODO.md。

### T5 Coach 按树排学期

- Coach（`coach.js`）现在按领域和阶段排 16 周。改成按节点：取本人阶段应到位而「还空着」的能力点，每个先排它 `needs` 里没碰过的知识点（条文页或记忆卡，半周），再排能力点挂的关（一周）。每周多一行「这周补的是哪一条、依据是什么」。排序是规则，不新增模型调用。

### T6 讲堂与合集按节点收

- 讲堂包切片（`lectures.js`）由讲者或管理员挂节点；一张知识海报对应的知识点自动成为该海报的标签。
- 合集（`collections.js`）加自动合集「某节点下全部入库内容」，节点页一键生成，范围沿用四档。

### T7 练兵题与研讨关按节点出题

- 练兵题（`drills.js`）与研讨关的题都标能力点，题干可引用 `needs` 里的知识点条文做「依据提示」；优秀作答进案例库自动带同一节点。一个能力点下面会自然长出「依据、题、答、案例」四样。

### T8 阶段认证改成按树算

- 现有证书（`certificates.js`）按路径走完算。加一种按树算的「阶段达标」：某阶段应到位的能力点有证据的比例、知识点答对过的比例，到门槛就可申领该阶段证书。门槛由本地运营方在后台设，默认能力点 70%、知识点 60%。只给本人与园长看，仍不排行。

### T9 空节点清单：给内容团队

- `/admin` 加「树上还空着的节点」：没挂内容的、能力点有案例没关卡的、知识点有条文没解读的、一个月没新增的。这是内容团队与名师讲堂的选题单。只给管理员看。

## 六、不借的

- 不做知识点刷题、正确率、复习提醒。
- 不做幼儿的知识树。树上没有「幼儿应达到」的节点。
- 不做热度：节点不显示浏览量、投蛋、下载数。
- 不做 AI 自动打标签。节点由人选，模型最多在表单里给三个「建议」。
- 不做 K12 的学段学科两维。学坊的两维是阶段和年龄班。
- 师德不做节点，不做「师德证据」。

## 七、顺序与体量

| 步 | 做什么 | 体量 |
|---|---|---|
| 1 | `tree-data.js` 建树：两根主干的领域与条目照《专业标准》抄；能力点先建现有 105 关与入库案例能挂上的；知识点先建这些能力点 `needs` 里要用到的，再加现有测验题能标上的 | 内容工作为主，两三个晚上 |
| 2 | T1 树页与两个接口、T2 字段与校验、测验题标知识点、存量按领域兜底 | 一两个晚上 |
| 3 | T3 发展地图两块、阶段筛、小程序同步 | 一个晚上 |
| 4 | T2 的条文解读页与记忆卡改按知识点、T4 工坊词表、T9 空节点清单 | 一个晚上 |
| 5 | T5、T6、T7、T8 | 各半个晚上，按内容团队需要再排 |

第 1 步做完就能看出树好不好用：105 关里有一半挂不到具体能力点，或能力点的 `needs` 大多写不出来，说明条目拆得不对，回头改树，不往下做。

## 八、要你定的

1. 条目层照《专业标准》原文抄，还是允许合并改写。建议照抄，出处清楚。
2. 叶子层谁定稿：本地运营方自己，还是请市教研员看一遍。这和 ROADMAP 十二节第 1 条是同一件事。
3. 先做哪两个领域：建议能力主干的「观察、记录与评价」「沟通与合作」（领域路径已做完，案例最多），知识主干配套先做「幼儿发展知识」。
4. 师德不进树这一条，是否同意。
