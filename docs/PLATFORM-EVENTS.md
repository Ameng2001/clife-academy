# 大课堂 × 柳州市学前教育数智服务平台：实操事件回传契约

给平台技术接口人看。大课堂每一关的「做」是在平台上实际操作一次；平台做完后把事件回传给大课堂，关卡页自动打勾，教师不截图、不手工登记。
登录对接见《平台登录对接契约》，本文只讲事件。

## 1. 边界

- 回传的是「哪个平台用户、做了清单上的哪件事、什么时候」。不传操作内容，不传任何幼儿数据。
- 事件名是闭合清单（第 3 节），不在清单上的拒收。清单随课程包版本变化，由大课堂提前给平台。
- 平台按用户标识回传，大课堂按登录契约里的 `uid` 找到人。还没在大课堂登录过的人回传会被拒（`no-user`），平台可丢弃或稍后重试。
- 方向单向：平台 → 大课堂。大课堂不回调平台。

## 2. 接口

```
POST https://{大课堂域名}/api/events
Authorization: Bearer {PLATFORM_EVENTS_KEY}      ← 大课堂发给平台的服务端密钥
Content-Type: application/json

单条  { "uid": "p-123", "event": "完成 1 次批量调整", "at": "2026-11-03T09:00:00+08:00", "ref": "adj-77", "id": "evt-0001" }
批量  { "events": [ { … }, { … } ] }               ← 一次最多 100 条
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `uid` | 是 | 平台用户唯一标识，与登录契约里的 `uid` 同一个 |
| `event` | 是 | 事件名，原样取自第 3 节清单 |
| `at` | 否 | 操作发生时间，ISO 8601 或毫秒时间戳；缺省按收到时间 |
| `ref` | 否 | 平台侧记录 id（那条调整、那次保存），用于去重与排错 |
| `id` | 否 | 幂等键；同一用户同一 `id` 只收一次 |

幂等规则：有 `id` 按 `id` 去重；没 `id` 但有 `ref` 按 `(event, ref)` 去重；两者都没有，每次回传算一次。建议平台带 `id` 或 `ref`，重试就不会重复计数。

应答：

```
200  { "accepted": 1, "duplicates": 0, "rejected": [] }
200  { "accepted": 2, "duplicates": 1, "rejected": [ { "i": 3, "code": "unknown-event" } ] }   ← 批量按条答，整体 200
400  { "error": "event refused", "code": "unknown-event" }      ← 单条：事件名不在清单
400  code: missing-event | bad-time | batch                      ← 缺事件名、时间不合法、批量超出 1–100
401                                                              ← 密钥不对
404  { "code": "no-user" }                                        ← 单条：uid 在大课堂没有账号
```

超时与重试：大课堂在 2 秒内应答。平台收到 5xx 或超时可重试，带 `id` 或 `ref` 即可安全重试。

## 3. 事件清单（首期 34 项）

按岗位路径列出，事件名需逐字一致。清单由大课堂课程包生成（`api/academy/events-data.js`），变更时大课堂提前一周通知。

| 岗位 | 事件名 |
|---|---|
| 保健医 | 三端各登录 1 次；新增或核对 1 个班级；完成 1 次批量调整；提交并撤销 1 条请假；语音录入 1 条晨检异常；全日观察·登记疾病 已保存；标记处理 1 次聚集预警；完成 1 条追踪与康复；批量导入 2 名幼儿档案；新建 1 个专案并录 1 次监测；AI 导入 1 份体检报告；生成 1 周食谱并调优 1 次 |
| 班级教师 | PAD 与小程序各登录 1 次；完成 1 次本班出勤确认；完成 1 篇课案初稿；归档 1 篇课案；排 1 周教学活动；上传 1 幅幼儿作品；审定 1 篇随手记；查看 1 次本班测评结果；选定 1 节体能课案；完成 1 节课案预习 |
| 保育员 | 完成 1 次铺设检查；完成 1 次电池更换；查看 1 次本班午睡；协助核对 1 次出勤 |
| 信息接口人 | 完成 1 次在线检查；提交 1 张报修工单 |
| 园长 | 打开工作台 1 次；指派 1 条待办；完成 1 次班级对比；完成 1 条复盘；生成 1 次补训通知；核对 1 次岗位权限 |

「N 次」类事件由平台在达到次数时回传一次即可，也可每次操作回传一次（大课堂只看有没有）。

## 4. 平台侧触发点（请平台确认）

每个事件对应平台的一个业务动作完成点（保存成功、提交成功、登录成功）。请平台接口人按清单逐条标注：对应哪个模块的哪个动作、在哪一层能拿到用户标识、是否已有事件总线或审计日志可以复用。

## 5. 测试

大课堂提供测试环境地址与测试密钥；平台用测试账号（每个岗位至少一个，已在大课堂登录过）回传，关卡页应在 10 秒内显示「平台已回传」。
大课堂侧的自动化测试在 `api/test/academy-events.test.js`。

## 6. 待对齐

1. 密钥发放与轮换方式；平台出口 IP 是否固定（大课堂可加白名单）。
2. 用户标识：与登录契约一致即可，请确认平台事件层拿到的是同一个 `uid`。
3. 第 4 节的触发点逐条确认，尤其「三端各登录 1 次」「PAD 与小程序各登录 1 次」这两个跨端事件由谁汇总。
4. 历史操作要不要补传（教师在学关之前已经做过的）：大课堂接受任何时间的事件，补传与否由平台定。
