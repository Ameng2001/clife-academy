# 积分资产设计（2026-10-22）

参照懂了鸭的资产体系。懂了鸭有三种资产：创作积分（内容创作消耗）、下载次数（注册送 10 次，下载打印别人作品扣）、鸭蛋（每日签到送，可赠给别人的作品，用户间流动）。它的总结是「有内容创作的，有内容消耗的，有社区促活的，有作品激励的」。

幼师学坊只保留**一种**可花的资产，叫**积分**，另外两种不照搬：下载次数不做（课程成果与案例的文件是外链，不计次、不设墙）；鸭蛋不做（教师间不流转任何资产，作品激励由平台发给分享者，不从别人账上扣；每日签到是教师厅〔2025〕2 号点名的强制打卡，不碰）。

## 一、只有一种资产：积分（2026-10-22 夜 59 定）

一开始写的是「学分是记录、积分是额度」两层。用户定：**只保留积分一种资产，不再设计学分。** 学习时长仍计继续教育学时（那是时长，不是资产）；证书、勋章、称号照旧按记录算，不是资产。

| | 积分 |
|---|---|
| 是什么 | 平台唯一的资产：可花的额度 |
| 从哪来 | 学、贡献、互动三类事件，自动到账（规则表每类记多少，运营后台可改，只影响之后的） |
| 去哪 | 教研工坊与接入工具的额度；教学物料商城 |
| 谁看得到 | 只有本人（钱包页与教研工坊统一，学坊不单独做） |
| 排行 | 不排 |

实现（`api/academy/points.js`）：学与贡献的事件走 honors.js 的事件记录（`ledger.grant`，一事一条），points.js 包一层，一记录就按规则表记积分；过关在客户端进度里，读余额时对账补记；走完路径、取得证书由 `ledger.learn` 按记录补记。旧的「学分兑积分」接口已删。

## 二、赚：三条途径

数字是默认值，运营方在后台「积分」一组改（`db.pointsRules.earn / interact`），改了只影响之后的事件。

**1. 学（PGC）**

| 事件 | 积分 | 已有 |
|---|---|---|
| 关卡过关（测验 ≥ 80%） | 10 | ✔ 客户端进度对账 |
| 走完一条路径（全部关过） | 50 | ✔ 夜 59 `ledger.learn` |
| 实践关作品通过点评 | 10 | ✔ 夜 59（关卡本身过关另记 10） |
| 取得证书（岗位认证 / 领域研修 / 骨干） | 100 | ✔ 夜 59 `ledger.learn` |
| 练习营结营（发过帖的营员） | 20 | ✔ 夜 59 |

「精品微课看完」不单独给：微课就是关卡的讲段，过关才算。

**2. 贡献（UGC）**

| 事件 | 积分 | 已有 |
|---|---|---|
| 专家案例入库 | 20 | ✔ |
| 课程成果入库 | 30 | ✔ |
| 研讨作答被精选 | 20 | ✔ |
| 斗课 / 共同体赛作品入库 | 20 | ✔ |
| 案例被改编入库（原作者记 adapted；改编者自己的入库记 case） | 20 / 20 | ✔ 夜 60（课程成果的改编随来源链再接） |
| 名师讲堂上台分享（管理员邀上某一场） | 50 | ✔ 夜 60，一场一次 |
| 园所分享日交页（园长） | 20 | ✔ 夜 60，一次分享日一园一次，改页不重复 |

**3. 互动**

互动是社区活起来的原因，所以给积分；但每一项都有上限。每一项都是「别人的真实使用」或「自己的真实付出」，不是点一下的事。

| 事件 | 积分 | 上限 | 已有 |
|---|---|---|---|
| 自己的案例 / 成果被标「用过，有效」 | 5 / 次 | 同一作品每天记 1 次，每月 20 次 | ✔ 夜 58 |
| 标别人「用过，有效」并写了一句怎么改的 | 2 / 次 | 每天 3 次 | ✔ 夜 58 |
| 答疑队列里的回答被提问者采纳 | 5 / 次 | 一题只记一次 | ✔ 夜 58 |
| 点评别人的作品（点评人） | 3 / 次 | 每天 5 次，一份提交只记一次 | ✔ 夜 58 |
| 练习营里的帖子 | 1 / 帖 | 一天一帖本来就限，改帖不重复记 | ✔ 夜 58 |

**不给积分的**：签到、在线时长、浏览、点赞、关注、邀请、连续登录、分享到朋友圈。这些要么是政策点名的，要么是刷得出来的。

## 三、花：两个去处

**1. 工具额度（已有）**：接入的工具服务端带 `TOOLS_API_KEY` 调 `POST /api/points/spend`，按 (tool, ref) 幂等扣减。工坊按课程起草扣，建议价：

| 工具 | 事 | 积分 |
|---|---|---|
| 教研工坊 | 主题式课程（按周） | 30 / 周 |
| 教研工坊 | 项目式课程（按周） | 40 / 周 |
| 教研工坊 | 单节活动 | 10 |
| 教研工坊 | 改编一门入库成果（`?from=`） | 原价 5 折 |
| 观察评价工具 | 生成一份量表 | 10 |
| 贝果实验室 | 一次创新课生成 | 20 |

定价原则：一个教师一学期认真走完两条路径（约 12 关 120 分 + 路径 100 + 证书 100）加分享一门课（30），攒下的积分够在工坊做两到三门课。学得多、分享得多的人，工坊基本不花钱；没学的人也能做，但得由园所给额度（见五）。

**2. 物料商城**（夜 61 已做：`api/academy/mall.js`、网页 `/mall`、小程序 `pages/mall`）：本地运营方上架**教学物料**，教师用积分换，运营方发货到园。

- 上什么：教具包、绘本、区角材料、耗材、名师讲堂线下场次名额、培训名额。**不上**购物卡、现金等价物、与教学无关的礼品。
- 谁上：本地运营方（管理员或区县管理员）在后台建商品：名称、说明、图、积分价、库存、范围（全平台 / 本区县 / 本共同体）、收货方式（寄到园 / 讲堂现场领）。
- 怎么换：教师从工坊的钱包页或学坊「我的」进商城，选物、确认收货园所（默认本园地址，不填个人地址）、扣积分、生成订单。运营方后台看订单、标发货、标签收；运营方可取消并退回积分。教师在订单发货前可取消。
- 不做：不做购物车、不做拼单、不做秒杀、不显示「已兑 N 件」、不显示热门榜。

## 四、规则（红线）

1. **不是货币**：不能充值、不能提现、不能换钱换卡、不可转赠、不可赠给别人的作品。对客材料里叫「积分」或「使用额度」，不叫「虚拟货币」，也不再提「学分」。
2. **不排行、不公开**：余额和明细只有本人看得到；园长看板看本园合计花在工坊的额度（用于预算），不列人。
3. **不与考核挂钩**：积分不进任何评价、晋级、绩效口径；平台不提供按人导出。
4. **只奖真实行为**：没有签到、在线时长、浏览、点赞；互动类有日上限、月上限，且必须有内容（一句话、一次采纳）。
5. **可审计**：每一笔有来源（事件、ref、时间），同一 (kind, ref) 只记一次；运营方后台能看到异常（一天内被同一人标「用过」多次的，自动不记）。
6. **可配置但不追溯**：比例与价格在后台改，只影响之后的事件；已到账的不重算。
7. **有效期**：暂不设过期。要设的话以学年为单位、提前一学期在钱包页提醒，不做月底清零。

## 五、园所额度

没学够的教师也要用工坊。园所可以有一个**园所额度池**：本地运营方按合同给园所充额度（这是合同里的事，不是教师的积分），园长在园长看板把额度分给教师（一次分配、可收回未用部分）。教师花的时候先扣园所分配的，再扣自己赚的。园所额度不进商城，只能用在工具上。

已做（夜 63，`api/academy/quota.js`）：一张流水 `db.orgQuotaLog`（充值 topup / 分配 alloc / 收回 recall / 扣减 spend），池子 = 充 − 分 + 收，某人在手 = 分 − 收 − 扣。
- 运营后台「积分」组：`POST /api/admin/quota/topup { org, n ≤ 100000, note }`，只有管理员，充了不能撤；`GET /api/admin/quota` 各园池子一览。
- 园长看板「园所额度」：`GET /api/org/quota`（池子、每人在手与用掉、流水）、`POST /api/org/quota/alloc { uid, n }`（本园教师，不含园长自己，≤ 池子）、`POST /api/org/quota/recall { uid, n? }`（不带 n 全收，只收没用掉的）。
- 工具扣减 `POST /api/points/spend`：先扣园所额度再扣积分，应答带 `fromQuota / fromPoints`；幂等按 (tool, ref) 在两本账上一起查；`GET /api/points/balance` 带 `quota` 与 `total`。工坊的钱包页按 `points`、`quota` 两行显示。
- 商城（`ledger.points.spend`）只看个人积分，额度在手也换不了物料。
- 教师看到：`GET /api/me/points` 的 `quota.left`，荣誉页积分 tile、我的页、小程序我的页一句「另有园所额度 N，只能用在工具上」。

## 七、不做的

- 不做鸭蛋式的用户间流转资产，不做「给作品投币」。
- 不做下载次数与下载墙。
- 不做每日签到、连续登录奖励、在线时长。
- 不做积分排行、「本周赚得最多」、「本园积分榜」。

- 不做付费充值积分：教师个人不花钱；园所额度走合同。
